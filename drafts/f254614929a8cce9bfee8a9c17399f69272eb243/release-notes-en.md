## Pico

- The C++ Pico bridge extends `--control-mode fdcc` and `--control-mode impedance` to dual arms. Each Grip independently enters and exits its arm's mode. A worker fault cancels both target streams and ends the session. Dual-arm ServoP remains the default; compliance modes do not use thumbstick J6 control. Host target periods are configured at 20ms per arm for FDCC and 5ms for impedance, rather than measured update rates. ([869d31b](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/869d31b834a3c0333d9172eac6c6d9a0d647a2d5))
- Adds `--fdcc-damping-factor` in \[0,1\], defaulting to 0.9, and `--fdcc-error-scale` with a test-entry range of \[0.1,4\], defaulting to 1. The former sets virtual integration velocity retention; the latter scales both pose and wrench PD output. These are separate from drive friction compensation. Pico retains the paired RCore default friction handling. ([869d31b](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/869d31b834a3c0333d9172eac6c6d9a0d647a2d5))
- Default impedance stiffness changes to `400,400,400,30,30,30`, and damping to `30,30,30,2,2,2`. Existing commands therefore use different controller gains. Adds `--impedance-profile hold` to restore the previous gains. Explicit `--impedance-stiffness` and `--impedance-damping` independently override the profile regardless of argument order. ([869d31b](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/869d31b834a3c0333d9172eac6c6d9a0d647a2d5))
- Adds `--fdcc-direct-target` and `--impedance-direct-target` to send approved targets directly, bypassing host target smoothing and speed/acceleration shaping. Each activation still starts at measured TCP and retains target validation, expiry and exit checks. FDCC direct mode requires `--fdcc-target-scale 1`. ([869d31b](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/869d31b834a3c0333d9172eac6c6d9a0d647a2d5))
- Adds `--impedance-joint-max-speed` with an explicit range of (0,180\] degrees/s, mutually exclusive with impedance direct mode. It limits steps along approved IK joint references, then uses FK to generate equilibrium poses. Long scheduling gaps contribute at most 20ms. This limits reference trajectories, without guaranteeing measured joint speeds. ([869d31b](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/869d31b834a3c0333d9172eac6c6d9a0d647a2d5))
- When `DisableCartesianImpedance()` returns 4311 during exit, the bridge makes up to three calls to continue settling, without sending new targets or reactivating. Persistent failure, other exit errors or failure to confirm mode exit cause the FDCC and impedance exit paths to request `EStop()`, then attempt `Disable()`. ([869d31b](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/869d31b834a3c0333d9172eac6c6d9a0d647a2d5))
- The Pico input expiry threshold changes from 250ms to 400ms. Robot-state and target-validation freshness checks remain independent. Compliance input expiry requires Grip release before reactivation. Dual-arm logs add input age, receive gaps, sequence and tracking status. Rejected joint-candidate logs distinguish measured J3/J5 boundary proximity, IK boundary proximity and branch crossings. ([869d31b](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/869d31b834a3c0333d9172eac6c6d9a0d647a2d5))
- Dual-arm startup reports SDK connection, command-source acquisition and reference-frame resolution. Exit requests are checked after initialization and between subsequent stages, with connection cleanup on cancellation. ([869d31b](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/869d31b834a3c0333d9172eac6c6d9a0d647a2d5))

## Common interfaces and other changes

- Adds the Linux C++ application `app_peripherals_keyboard_bridge` for one arm or independent dual-arm key groups. Cartesian mode calls `Motion().ServoRelativeP()`; joint mode calls `Motion().ServoJ()`. Supports `--frame base|tool` and robot-free `--dry-run`. Live connections require explicit `--enable-motion`. ([869d31b](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/869d31b834a3c0333d9172eac6c6d9a0d647a2d5))
- Keyboard control supports held keys and combinations in a local X11 terminal. SSH, Wayland or `--terminal` use bounded jogs of 1mm or 0.5° per keypress. Space toggles input enablement. Tab waits for both arms to settle before switching Cartesian/joint space and leaves input paused. Focus loss or input desynchronization pauses control. Exit holds Servo targets, requests motor disable and checks feedback. ([869d31b](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/869d31b834a3c0333d9172eac6c6d9a0d647a2d5))

## SDK, build and release

- Linux SDK builds add an installed keyboard application target. The release workflow includes it in the SDK bridge package and configures a `--help` loading check. X11 held-key support uses optional XCB and requires the `libxcb1` runtime; builds without XCB retain terminal jogs. Pico teleoperation still requires a source build with a matching SDK and remains excluded from default prebuilt packages. ([869d31b](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/869d31b834a3c0333d9172eac6c6d9a0d647a2d5))

## Needs verification

- Source and workflow changes do not establish hardware validation, achieved update rates or availability of required APIs in released SDK binaries. This review was read-only; no builds or tests were run.
- The new Chinese quickstart states that the FDCC wrench low-pass changed from 10Hz to 5Hz. This range contains no corresponding controller implementation change, so that behavior and its delivery version remain unverified.
