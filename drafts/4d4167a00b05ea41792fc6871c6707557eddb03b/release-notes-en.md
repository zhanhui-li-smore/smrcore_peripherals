## Pico

- Add `--single-arm` to control a standalone arm with the physical right controller through an SDK `Single` instance. Startup does not require the left controller. Mapping uses the `base` frame; `face-to-face` does not swap controllers. Dual-arm ServoP remains the default. ([f6e46d1](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/f6e46d1afa1ea5240ad1a5d45b391ac2a308bb96))
- Add `--single-mapping-yaw` to rotate single-arm translation and rotation increments around base Z, from −180° to 180°, defaulting to 0°. Add `--no-gripper` to skip DH gripper initialization and Trigger control in single- or dual-arm operation. ([f6e46d1](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/f6e46d1afa1ea5240ad1a5d45b391ac2a308bb96))
- Add single-arm `--control-mode fdcc|impedance`, corresponding to `PicoControlMode::Fdcc` and `PicoControlMode::CartesianImpedance`. Releasing Grip requests exit from compliance mode to hold; re-engaging anchors to the measured TCP. Both modes disable thumbstick J6 while retaining gripper and direction mapping. ([f6e46d1](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/f6e46d1afa1ea5240ad1a5d45b391ac2a308bb96))
- FDCC uses `SetFdCartesianAdmittancePoseTarget` at up to 50 Hz. Default translation target shaping uses 0.30 m/s, 1.2 m/s² and gain 8/s, with velocity feedforward of 0.5. `--fdcc-target-scale` optionally adds translation lead capped at 30 mm. These settings constrain targets, not measured motion. ([f6e46d1](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/f6e46d1afa1ea5240ad1a5d45b391ac2a308bb96))
- Impedance mode writes equilibrium poses through `SetCartesianImpedanceTarget` at up to 200 Hz. `--impedance-stiffness` and `--impedance-damping` accept six XYZ/RX/RY/RZ values. Target shaping is configured separately from stiffness and damping. DDS writes have no delivery acknowledgement. ([f6e46d1](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/f6e46d1afa1ea5240ad1a5d45b391ac2a308bb96))
- When input remains fresh but target approval has not renewed for 200 ms, compliance modes retain their mode and freeze the last sent equilibrium. Tracking resumes after a successful check. Stale input or Jacobian data and rejected candidates pause operation; rearming requires fresh released-Grip input and confirmed mode 0. Stale state, mode loss or write failure ends the session. ([f6e46d1](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/f6e46d1afa1ea5240ad1a5d45b391ac2a308bb96))
- Add checks for nonfinite input, invalid quaternions and outgoing targets. Single-arm operation ignores unused left-hand data. Compliance modes use measured-Jacobian slowdown without rejecting candidate endpoints solely for reaching condition number 60. IK reachability, joint clearance and FK consistency checks remain. ServoP retains its candidate-boundary policy. ([f6e46d1](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/f6e46d1afa1ea5240ad1a5d45b391ac2a308bb96))
- Add diagnostics for input age, check duration, shaping gaps and tracking errors. `--help-advanced` exposes tuning options while regular help focuses on operation. New options are available through `PicoTeleopOptions`; ranges and mode combinations are checked before connection. ([f6e46d1](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/f6e46d1afa1ea5240ad1a5d45b391ac2a308bb96))

## SDK, build and release

- Fix unnecessary private development dependencies when consuming the shared library through `find_package(smrcore_peripherals CONFIG)`. Shared-library configuration no longer looks up `Threads` or `nlohmann_json`. Static consumers still resolve them, and the exported target remains `smrcore::peripherals`. ([abe9328](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/abe93282b2a87a92ddf010986665f6be9263c656))
- The website, manual and Release note generator now reads bilingual fragments from immutable Git version ranges. Later edits do not rewrite published notes; uncommitted content and `misc` fragments are excluded. Reviewed summaries retain precedence, commit-note fallback remains, and languages and categories are validated. The website workflow provides Markdown preview artifacts. ([4d4167a](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/4d4167a00b05ea41792fc6871c6707557eddb03b))

## Documentation

- Add Chinese and English guidance for single-arm Pico operation, compliance modes, tuning and pause/exit behavior. The existing Python launcher forwards these options to the C++ bridge. Pico teleoperation still requires an explicit `--with-sdk ON --with-pico ON` build. The current prebuilt SDK bridge workflow keeps Pico disabled and builds SpaceMouse and force/torque integration. ([f6e46d1](https://github.com/zhanhui-li-smore/smrcore_peripherals/commit/f6e46d1afa1ea5240ad1a5d45b391ac2a308bb96))
